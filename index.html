⚙️ Chapitre 2 — Gestion des Processus & Ordonnancement Cours + TD
📌Programme vs Processus & PCB
Programme : Fichier statique sur disque. Entité passive.
Processus : Programme en cours d'exécution. Entité dynamique avec : code, données, pile, registres, et son propre PCB.
Un programme → plusieurs processus possible.
PCB — Process Control Block :
Structure de données qui contient tout sur le processus :
• PID (identifiant unique)
• État courant (Prêt/Actif/Bloqué...)
• Valeurs des registres CPU
• Compteur ordinal (prochaine instruction)
• Priorité, table de pages, ressources allouées
→ Le PCB est la carte d'identité du processus
🔄Les 5 États d'un Processus
📌 Un seul processus est Actif à la fois (mono-CPU). Plusieurs peuvent être Prêts ou Bloqués simultanément.
🏛️Les 3 Niveaux d'Ordonnanceurs + Dispatcher
🔴 Long Terme (LTS)
Charge les programmes du disque → MC. Crée les PCBs. Insère dans LISTE_PRETS.
Applique : FIFO ou SJF
Contrôle le degré de multiprogrammation.
🟡 Moyen Terme (MTS)
Décharge (swap out) / recharge (swap in) des processus entre MC et disque.
Utilisé quand la MC est saturée.
🟢 Court Terme (STS)
Choisit quel processus Prêt → CPU. Très fréquent (ms).
Applique : FCFS, SJF, RR, Priorités...
⚡ Dispatcher (Répartiteur) :
Programme système qui donne concrètement le CPU au processus sélectionné par le STS.
Étapes : (1) PROCESSUS_COURANT ← @PCB du processus actif (2) Charge registres CPU depuis PCB (3) Charge compteur ordinal (4) Passe en mode Esclave.
→ En multiprocesseur : CPU1 en priorité, puis CPU2. C'est toujours le Dispatcher qui oriente.
📊Critères de Performance — Formules Exactes
⏱ Turnaround (Temps de Traitement / TT)TT = Temps_Fin - Temps_Arrivée

Ou : TT = attente chargement MC + attente file Prêts + exécution + E/S

⏳ Waiting Time (Temps d'Attente / TA)TA = TT - Burst_Time

= Somme des temps passés dans la file des Prêts

⚡ Response Time (Temps de Réponse / TR)TR = Temps_Début_Exécution - Temps_Arrivée_MC

= Temps avant premier passage CPU. Important pour systèmes interactifs.

📊 MoyennesTMT = Σ TT_i / N    TMA = Σ TA_i / N
🔢Algorithmes d'Ordonnancement — Tous les Cas

① FCFS — First Come First Served (Non-préemptif)

Premier arrivé, premier servi. Liste FIFO des Prêts. Défaut Effet convoi : un long processus bloque tout le monde.
Exemple du cours : P1(24), P2(3), P3(3) → ordre FCFS : P1→P2→P3 = TT_moy = (24+27+30)/3 = 27
Si ordre SJF : P2→P3→P1 = TT_moy = 13 → FCFS est très sensible à l'ordre d'arrivée

② SJF — Shortest Job First (Non-préemptif) ⭐ TRÈS FRÉQUENT EXAM

Parmi les processus Prêts → choisir celui avec le burst_time le plus court. Égalité → FCFS.
Optimal pour minimiser le temps moyen d'attente.
Exemple du cours : P1(6), P2(3), P3(8), P4(7) → ordre SJF : P2(3)→P1(6)→P4(7)→P3(8)
Gantt : 0——3——9——16——24 → TT_moy = (9-0)+(3-0)+(24-0)+(16-0))/4 = 13

③ SRTF — Shortest Remaining Time First (Préemptif = SJF préemptif)

À chaque arrivée d'un nouveau processus → comparer son burst avec le temps restant du processus Actif. Si nouveau < restant → préemption.
Exemple cours : P1(0,8) P2(1,4) P3(2,9) P4(3,5) → TT_moy = ((17-0)+(5-1)+(26-2)+(10-3))/4 = 13
FCFS même cas = 15.25 → SRTF meilleur

④ Priorités Non-Préemptif / Préemptif

Chaque processus a une priorité (0 = plus haute). Problème : Famine (Starvation) → un processus de basse priorité peut attendre indéfiniment.
Solution : Vieillissement (Aging) — la priorité augmente avec le temps d'attente.
SRTF = Priorité préemptive où priorité = 1/burst_restant

⑤ Round Robin — RR (Préemptif) ⭐ Quantum

Quantum q : chaque processus reçoit q unités de CPU. S'il ne finit pas → retour en fin de LISTE_PRETS. Déclenché par interruption d'horloge.
Exemple cours : P1(17), P2(3), P3(4), P4(2), Quantum=4
Gantt : P1(0-4), P2(4-7), P3(7-11), P4(11-13), P1(13-17), P1(17-21)...
Équitable Plus de commutations de contexte
Petit quantum → meilleur TR mais overhead élevé. Grand quantum → comme FCFS.

⑥ Files Multi-niveaux (sans / avec feedback)

Sans feedback : processus assigné définitivement à une file (Foreground/Background). Chaque file a sa politique (RR pour Foreground, FCFS pour Background). Préemption entre niveaux.
Avec feedback : processus peut changer de file selon son comportement. Quantum croissant par niveau. Favorise les processus courts (interactifs).

🧮 Chapitre 4 — Gestion de la Mémoire Centrale Cours + TD8 pts exam
📍Adressage : Logique vs Physique
Adresse Logique : Adresse vue par le CPU/processus. Générée par le programme.
Adresse Physique : Adresse réelle dans la RAM. Vue par l'unité de gestion mémoire (MMU).
Conversion (allocation contiguë)Adresse_Physique = Adresse_Logique + Base
MMU (Memory Management Unit) : Circuit matériel qui fait la traduction adresse logique → physique automatiquement.
💡 Synonymes MC : RAM = Mémoire Vive = Mémoire Principale = Mémoire Physique = Mémoire Centrale
🏗️Allocation Contiguë — Partitions

🔒 Partitions Fixes (Statiques)

Mémoire divisée en N partitions au démarrage. Taille fixe (égale ou non). Chaque partition = 1 processus max.
Fragmentation INTERNE espace perdu À L'INTÉRIEUR de la partition.
Problème file : processus attend même si autre partition libre.
Solution File unique + Best Fit (choisir la + petite partition libre suffisante)

🔄 Partitions Variables (Dynamiques)

Partitions créées selon la taille exacte du processus.
Fragmentation EXTERNE trous éparpillés, chacun trop petit.
Solution : Compactage déplacer les processus pour fusionner les trous. Coûteux (arrêt de l'exécution).
Algorithmes de placement :
• First Fit : 1er trou suffisant
• Best Fit : + petit trou suffisant
• Worst Fit : + grand trou
• Next Fit : First Fit depuis la dernière position

Exemple TD — Best Fit / First Fit

Trous libres : 100Ko, 500Ko, 200Ko, 300Ko, 600Ko
Processus : A(212Ko), B(417Ko), C(112Ko), D(426Ko)
First Fit : A→500Ko, B→500Ko(reste 83), C→200Ko, D→600Ko
Best Fit : A→300Ko(reste 88), B→500Ko(reste 83), C→200Ko(reste 88), D→600Ko(reste 174)
Best Fit = meilleure utilisation de la mémoire dans cet exemple
📄Pagination ⭐ Cœur de l'examen
Principe : MC divisée en cases (frames) de taille fixe. Processus divisé en pages de même taille. Une page → n'importe quelle case libre.
Avantage Pas de fragmentation externe. Inconvénient Fragmentation interne possible (dernière page).
Numéro de page (N°P)N°P = Adresse DIV Taille_Page
Déplacement / Offset (d)d = Adresse MOD Taille_Page
Adresse physique@Phys = (N°Case × Taille_Page) + d
Nombre de pages d'un processusNb_Pages = ⌈ Taille_Proc / Taille_Page ⌉
Fragmentation interne (dernière page)Frag = Taille_Page − (Taille_Proc MOD Taille_Page)
Si MOD=0 → Frag_interne = 0

Exemple TD3 Exercice 3

MC = 10 cases, taille case = 1000 mots.
P1=1600 mots, P2=3000 mots, P3=1000 mots

P1 : ⌈1600/1000⌉ = 2 pages. Gaspillage = 2000−1600 = 400 mots
P2 : ⌈3000/1000⌉ = 3 pages. Gaspillage = 0 mots (exactement 3×1000)
P3 : ⌈1000/1000⌉ = 1 page. Gaspillage = 0 mots

Traduction d'adresses

Adresse 1200 du P1 (taille page=1000) :
N°P = 1200 ÷ 1000 = 1 | d = 1200 MOD 1000 = 200
Table pages P1 : Page1 → Case5
@Phys = (5×1000)+200 = 5200

🔄Mémoire Virtuelle & Algorithmes de Remplacement ⭐
Pagination à la demande : on ne charge en MC que les pages nécessaires. Si une page est absente → Défaut de page (Page Fault) → chargement depuis le disque.
Si MC pleine → il faut remplacer une page victime.
⚠️ Règle fondamentale : Si MC = 1 seule case → chaque référence = 1 défaut de page → Nb_Défauts = Nb_Références

① FIFO — First In First Out

Remplacer la page la plus ancienne en mémoire (entrée en premier). Simple à implémenter. Peut être sous-optimal.
Exemple cours (3 cases, chaîne: 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1) : 15 défauts

② Optimal (OPT)

Remplacer la page dont la prochaine utilisation est la plus éloignée dans le futur.
Optimal → minimum de défauts possible. Mais impossible en pratique (nécessite le futur).
Même exemple : 9 défauts (référence uniquement)

③ LRU — Least Recently Used ⭐ EXAM

Remplacer la page la moins récemment utilisée (la + longtemps sans être référencée).
Bonne approximation de l'Optimal. Faisable en pratique.
Même exemple : 12 défauts

④ LFU / MFU (comptage)

LFU : remplace la page la moins fréquemment utilisée (compteur le + petit) → 11 défauts même exemple.
MFU : remplace la page la plus fréquemment utilisée → 14 défauts (souvent pire).
📊 Classement : OPT < LFU ≤ LRU ≤ FIFO ≤ MFU (nombre de défauts, de + petit au + grand)

المبدأ: الذاكرة الفيزيائية تُقسَّم إلى خانات (Cases) بحجم ثابت. البرامج تُقسَّم إلى صفحات (Pages) بنفس الحجم. صفحة واحدة في أي خانة حرة. ميزة: لا تجزئة خارجية
رقم الصفحةرقم الصفحة = العنوان ÷ حجم الصفحة (قسمة صحيحة)
الإزاحةd = العنوان MOD حجم الصفحة

  • LFU/MFU — بناءً على عدد الاستخدامات

⚡Définition Complète d'une Interruption
Définition exacte : Une interruption est un signal déclenché par un événement externe ou interne à la machine, qui provoque l'arrêt immédiat du programme en cours d'exécution — à un point appelé point observable ou interruptible (entre deux opérations élémentaires) — au profit d'un programme plus prioritaire appelé Traitant d'interruption / ISR (Interrupt Service Routine) / RIT (Routine d'Interruption). Ensuite, le programme interrompu reprend son exécution là où il s'était arrêté.
Pourquoi les interruptions ? (vs Polling)
Polling (ancien) : le CPU vérifie en boucle l'état des ressources → gaspillage de cycles CPU.
Interruption (solution) : au lieu que le CPU contrôle continuellement, c'est la ressource qui informe le CPU au moment significatif. → Économie de temps CPU, meilleure réactivité.
📊2 Modes d'Exécution — Base des Interruptions
Mode Esclave (Utilisateur / User)
Accès restreint aux ressources. Certaines instructions interdites (pas d'accès direct aux périphériques). Peut être interrompu. Le programme utilisateur s'exécute dans ce mode.
→ Pour accéder aux ressources protégées : doit passer par SVC
Mode Maître (Superviseur / Noyau / Kernel)
Accès sans restriction (mémoire, périphériques, interruptions...). Seul le noyau du SE s'exécute dans ce mode.
→ Le Traitant d'interruption s'exécute en mode Maître.
🔀Types d'Événements et d'Interruptions

🔁 Événements SYNCHRONES (liés au programme)

1. Déroutements (Traps / Exceptions) :
Anomalies dans l'exécution : division par zéro, dépassement de capacité (overflow), instruction interdite, accès zone protégée, instruction inexistante.
→ Ne peuvent pas être masqués (seulement supprimés). Traitement immédiat.

2. Appels au Superviseur (SVC — SuperVisor Call) :
Instruction spéciale qui permet à un programme utilisateur d'accéder à un service SE (E/S, allocation mémoire...). Volontaire, synchrone, passage automatique Mode Esclave → Mode Maître.

🎲 Événements ASYNCHRONES (extérieurs)

Événements imprévisibles, indépendants du programme en cours :

1. Interruptions matérielles externes :
• Fin d'opération d'E/S (disque, clavier, réseau...)
• Signal d'horloge (clock) → pour le quantum RR
• Pannes matérielles

Exemples : Périphériques qui "sonnent" pour dire que leur opération est terminée.

⚙️Mécanisme Complet de Gestion d'une Interruption

Structure d'un Traitant d'Interruption (RIT) — Structure Exacte à Connaître :

Traitant_Iti :
1. Sauvegarder le grand contexte (registres généraux) → Sauver(Zone_i / PCB)
2. Traiter la cause de l'interruption (programme spécifique)
3. Restaurer le grand contexte → Restaurer(Zone_i / PCB)
4. Restaurer le mode d'exécution + charger le compteur ordinal → LPSW(ancien-mep-Iti)
→ Retour automatique au programme interrompu

Structure d'un SVC (Appel Superviseur) — À Connaître :

Traitant_SVC :
1. Sauver le contexte du programme demandeur
2. Vérifier la nature de la requête
3. Vérifier les arguments (paramètres)
4. Vérifier les droits du demandeur
5. Exécuter la demande
6. Restaurer le contexte du demandeur
7. Retour vers le demandeur
🧠PSW, Contexte et LPSW ⭐ Très important
Contexte du Processeur = 2 parties :
• Grand Contexte : registres généraux (modifiables par le programme)
• Petit Contexte : MEP / PSW (registres spéciaux, inaccessibles par l'utilisateur)

MEP / PSW (Mot d'État du Processeur / Processor Status Word) :
Contient 4 champs :
Activité Actif ou En Attente
Mode Maître ou Esclave
Masquage Masqué ou Démasqué
C.O. Compteur Ordinal = adresse prochaine instruction
Commutation de contexte lors d'une interruption iti :
(a) Ranger le PSW courant → Ancien_MEP_iti
(b) Charger un nouveau PSW → Nouveau_MEP_iti
Le Compteur Ordinal prend l'adresse du traitant → exécution du RIT

LPSW (Load Process Status Word) :
Instruction qui charge l'ancien PSW sauvegardé → restaure l'état exact du processeur → le programme interrompu reprend exactement où il s'était arrêté.
C'est le mécanisme de "retour de l'interruption".

Vecteur d'Interruptions

Table en mémoire (zone basse) qui associe chaque N° d'interruption k à l'adresse du traitant correspondant.
vi[k] = adresse du Traitant de l'interruption k
Lors d'une interruption : le CPU reçoit un index k → accède à vi[k] → saute au traitant.
Le vecteur d'interruptions est dans une zone inaccessible aux programmes utilisateurs.

Contrôleur d'Interruptions

Circuit spécial de la carte mère (hors CPU). Reçoit les IRQ (Interrupt ReQuest) des périphériques, les met en file d'attente, les envoie une par une au CPU via la broche INTR.
Avant d'envoyer la suivante : attend le signal INTA (Interrupt Acknowledge) du CPU.
→ Sans le contrôleur : il faudrait une broche par périphérique sur le CPU.
🎛️Priorités, Masquage et États des Interruptions
Priorité 0 = la plus haute (la plus urgente)
Priorité N = la plus basse.
Si plusieurs interruptions simultanées → la plus prioritaire est traitée en premier.
Le traitant d'une interruption peut être lui-même interrompu par une interruption de priorité supérieure → Interruptions en cascade
3 États d'un niveau d'interruption :
Masqué : mémorisée mais non traitée (retardée). Les interruptions de même niveau ou niveau inférieur sont masquées pendant le traitement d'une interruption.
Armé : peut interrompre le CPU.
Désarmé : désactivé, demandes perdues (comme si la cause n'existe pas).
En attente : peut être prise en compte si : aucune priorité supérieure active ET CPU dans un point interruptible.
📌 Registre d'interruption : chaque type d'interruption a 1 bit. Un périphérique peut seulement modifier son propre bit.
⚡الفصل 3 — إدارة الانقطاعات (Cours فقط)
🎯 لا يوجد TD لهذا الفصل → أسئلة نظرية بحتة. يجب حفظ كل التعريفات والآلية الكاملة.
تعريف الانقطاع: إشارة ناتجة عن حدث داخلي أو خارجي تُوقف تنفيذ البرنامج الحالي فوراً عند نقطة قابلة للانقطاع، لتنفيذ برنامج أكثر أولوية يُسمى مُعالج الانقطاع (ISR/RIT). بعد الانتهاء، يستأنف البرنامج المنقطع من حيث توقف.
لماذا الانقطاعات؟
بدلاً من أن يتحقق المعالج باستمرار (Polling = مضيعة وقت)، تُبلّغ الموارد المعالجَ فقط عند الحاجة → توفير في وقت المعالج.

أنواع الأحداث

  • متزامنة (Synchrones): دوّار (Trap) — قسمة على صفر، تجاوز، تعليمة محظورة. واستدعاء المشرف (SVC).
  • غير متزامنة (Asynchrones): نهاية عملية إدخال/إخراج، إشارة الساعة، أعطال مادية.

المفاهيم الأساسية للحفظ

  • PSW / MEP : سجل يحتوي على (الحالة، النمط، القناع، العداد الترتيبي). يُحفظ عند كل انقطاع.
  • LPSW : تعليمة تُعيد تحميل PSW المحفوظ → استئناف البرنامج المنقطع.
  • متجه الانقطاعات : جدول يربط رقم الانقطاع k بعنوان معالجه vi[k].
  • متحكم الانقطاعات : دائرة إلكترونية تستقبل طلبات IRQ من الملحقات وترسلها واحدة تلو الأخرى للمعالج.
  • الإخفاء (Masquage) : تعطيل مؤقت لانقطاع → يُحفظ ثم يُعالج لاحقاً.
  • التجريح (Armement) : تفعيل انقطاع. نزع التجريح → طلبات مفقودة.
  • SVC : تعليمة تتيح لبرنامج المستخدم طلب خدمة من نظام التشغيل (انتقال تلقائي: عبد→سيد).

هيكل مُعالج الانقطاع (RIT)

1. حفظ السياق الكبير (المسجلات العامة) — Sauver(Zone)
2. معالجة سبب الانقطاع
3. استعادة السياق الكبير — Restaurer(Zone)
4. LPSW(ancien-MEP) → العودة للبرنامج المنقطع

🔄Méthode Pas-à-Pas — LRU, FIFO, Optimal
🔴 FIFO — Méthode :
1. Défaut → chercher une case vide.
2. Si plein → expulser la page entrée la première (la plus ancienne).
Tenir un pointeur circulaire ou noter l'ordre d'entrée.
🟢 LRU — Méthode :
1. Défaut → chercher une case vide.
2. Si plein → expulser la page la moins récemment utilisée (la plus longtemps non référencée).
Regarder en arrière dans la chaîne.
🔵 Optimal — Méthode :
1. Défaut → chercher une case vide.
2. Si plein → expulser la page dont la prochaine utilisation est la plus éloignée dans le futur.
Si une page ne sera plus utilisée → c'est elle la victime.
💡 Ordre des défauts (du + efficace au - efficace) : Optimal ≤ LFU ≤ LRU ≤ FIFO ≤ MFU
⚡Points Clés à Retenir — Distinctions Importantes
Scheduler vs Dispatcher :
Scheduler (STS) = choisit quel processus aura le CPU.
Dispatcher = donne réellement le CPU au processus choisi (charge les registres, change le mode).
Préemptif vs Non-préemptif :
Non-préemptif : processus garde CPU jusqu'à fin ou blocage volontaire.
Préemptif : CPU peut être retiré à tout moment (quantum RR, nouveau processus plus court, priorité supérieure).
Fragmentation Interne vs Externe :
Interne : espace perdu DANS une partition/page déjà allouée.
Externe : espace libre total suffisant mais dispersé en petits morceaux inutilisables.
Programme → Processus :
Le programme devient processus au moment où le LTS le charge en mémoire centrale et crée son PCB. Pas à l'instant de sa demande!

⚡ Exercice 3 — Questions de Cours : Interruptions (possible exam)

Q1
Définissez une interruption. Pourquoi est-elle préférable au polling ?
2 pts
Définition : Une interruption est un signal déclenché par un événement externe ou interne à la machine, qui provoque l'arrêt immédiat du programme en cours (à un point observable/interruptible), pour exécuter un traitant d'interruption (ISR/RIT). Après le traitement, le programme interrompu reprend exactement là où il s'était arrêté.

Avantage vs Polling : Le polling oblige le CPU à vérifier en permanence l'état des ressources → gaspillage de cycles CPU. Avec les interruptions, c'est la ressource elle-même qui informe le CPU au moment significatif → économie de temps CPU, réactivité immédiate, meilleure performance globale.
Q2
Quels sont les 4 champs du PSW / MEP ? Quel est le rôle de l'instruction LPSW ?
2 pts
PSW / MEP contient 4 champs :
1. Activité : état du CPU (Actif ou En Attente)
2. Mode : Maître (superviseur) ou Esclave (utilisateur)
3. Masquage : interruptions activées ou masquées
4. Compteur Ordinal (C.O.) : adresse de la prochaine instruction à exécuter

LPSW (Load Process Status Word) :
Instruction qui restaure le PSW sauvegardé (Ancien_MEP_iti) → recharge le contexte du processeur à l'état exact avant l'interruption → le programme interrompu reprend son exécution là où il avait été arrêté. C'est l'acquittement / la "sortie" du traitant d'interruption.
Q3
Différenciez : Déroutement (Trap), SVC et Interruption matérielle. Donnez un exemple de chaque.
2 pts
Déroutement (Trap / Exception) :
Interruption interne synchrone causée par une anomalie dans l'exécution du programme. Ne peut pas être masqué.
Exemple : division par zéro, débordement arithmétique, instruction illégale, accès à une zone mémoire protégée.

SVC (SuperVisor Call / Appel Superviseur) :
Instruction spéciale qui permet à un programme utilisateur (mode Esclave) d'accéder volontairement à un service du SE (mode Maître). Point d'entrée unique et sécurisé vers le noyau.
Exemple : demande d'E/S, allocation de mémoire, création d'un processus.

Interruption matérielle externe :
Interruption asynchrone causée par un périphérique ou un événement extérieur au CPU, imprévisible.
Exemple : fin de lecture disque, touche clavier enfoncée, signal d'horloge (expiration du quantum RR).
Q4
Décrivez le mécanisme de commutation de contexte lors d'une interruption iti. Que contient le vecteur d'interruptions ?
2 pts
Commutation de contexte (hardware, opération indivisible) :
(a) Sauvegarder le PSW courant → Ancien_MEP_iti
(b) Charger le nouveau PSW → Nouveau_MEP_iti (dont le C.O. pointe vers le traitant de iti)
→ Le traitant s'exécute et sauvegarde le grand contexte (registres généraux) → Sauver(Zone)
→ Traitement de la cause → Restaurer(Zone) → LPSW(Ancien_MEP_iti) → reprise du programme.

Vecteur d'interruptions :
Table en zone basse de la mémoire centrale (inaccessible aux programmes utilisateurs).
Structure : vi[k] = @Traitant_de_l'interruption_k
Chaque case contient l'adresse du traitant correspondant à l'interruption de type k.
Permet une identification et un branchement rapide vers le bon traitant.
Q5
Expliquez les états Masqué, Armé/Désarmé. Qu'est-ce que la gestion des interruptions en cascade ?
2 pts
État Masqué : L'interruption est mémorisée mais non traitée. Elle est retardée jusqu'à la levée du masquage. Pendant le traitement d'une interruption de priorité P, les interruptions de priorité ≤ P sont automatiquement masquées.

État Armé : L'interruption peut interrompre le CPU normalement.
État Désarmé : L'interruption est complètement désactivée. Toute demande est perdue (pas mémorisée). Utilisé quand un équipement ne doit plus jamais interrompre.

Interruptions en cascade : Pendant le traitement d'un traitant d'interruption iti, une interruption de priorité supérieure itj peut survenir. itj interrompt le traitant de iti, qui est mis en attente. Le traitant de itj s'exécute, puis retourne au traitant de iti, qui finit, puis retourne au programme original. → Imbrication possible sur plusieurs niveaux selon la hiérarchie des priorités.

  • Fragmentation externe = تجزئة خارجية (مساحة حرة مشتتة)
  • Défaut de page = خطأ الصفحة — الصفحة غير موجودة في الذاكرة
